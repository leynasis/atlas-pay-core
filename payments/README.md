# Atlas Pay 0.3

Локальная платёжная система на базе Dash Core: кабинет продавца, счета, QR, отдельный кошелёк покупателя и возвраты с подтверждением продавца. Все платежи новой версии проходят в **трёхузловой devnet `atlas-local-v1`**.

Название временное. Здесь используются тестовые DASH без денежной стоимости. Публичная монета, международный приём реальных платежей и фиатные выплаты ещё не запущены.

## Запуск

Нужны Node.js 22.13+ и npm. Установка узла поддерживает macOS и Linux ARM64/x64; проверенная среда — macOS ARM64.

```sh
cd payments
npm ci
npm run demo
```

Первый запуск загружает Dash Core 23.1.8 с проверкой SHA-256, создаёт три узла с отдельными кошельками и добывает тестовые монеты. На macOS ARM64 официальные CLI при необходимости получают локальную ad-hoc подпись после проверки архива; системные настройки безопасности не меняются.

Откройте **http://127.0.0.1:4173**. Команда запускает три приложения:

| Адрес | Назначение |
|---|---|
| `http://127.0.0.1:4173` | Кабинет продавца, счета, checkout и мониторинг сети |
| `http://127.0.0.1:4174` | Кошелёк покупателя: подготовка и явная подпись платежа |
| `http://127.0.0.1:4175` | Кошелёк продавца: подготовка и явная подпись возврата |

## Платёж и возврат

1. Создайте счёт, например на `0.125` тестовых DASH, и откройте страницу оплаты.
2. Перейдите в кошелёк покупателя и нажмите «Подготовить». Проверьте адрес, сумму, комиссию, итог, сдачу и сеть.
3. Отдельно подтвердите подпись и отправку. Открытие ссылки и подготовка сами по себе не отправляют монеты.
4. Вернитесь к счёту. После обнаружения перевода создайте тестовый блок; статус изменится на оплаченный.
5. Для возврата скопируйте адрес получения из кошелька покупателя, укажите его в счёте продавца и создайте запрос возврата.
6. В отдельном кошельке продавца подготовьте, проверьте и подтвердите возврат. После ещё одного тестового блока счёт покажет завершённый возврат.

QR содержит **ссылку на локальную страницу оплаты**, не запрос основной сети Dash. Все адреса localhost доступны только на этом компьютере; это пока не касса для клиентов в интернете.

Перезагрузка страницы восстанавливает сохранённую операцию. Повторное подтверждение уже отправленного запроса возвращает ту же транзакцию. Отмена доступна только для неподписанного подготовленного запроса. При неопределённом результате отправки сохраняются подписанные байты и txid — новый платёж автоматически не создаётся.

Частичная внешняя оплата учитывается, но блокирует новую автоматическую оплату полной суммы: требуется проверка продавцом. Переплата и позднее поступление отражаются в счёте. Возврат в этой версии — весь подтверждённый полученный объём; адрес явно задаёт продавец. Дополнительные поступления и конфликт возврата требуют проверки.

## Команды

| Команда | Назначение |
|---|---|
| `npm run demo` | Запустить devnet, собрать интерфейс и запустить три приложения |
| `npm start` | Запустить три приложения после сборки |
| `npm run start:merchant` | Только кабинет продавца, порт 4173 |
| `npm run start:customer-wallet` | Только кошелёк покупателя, порт 4174 |
| `npm run start:merchant-wallet` | Только кошелёк возвратов, порт 4175 |
| `npm run lab:start` / `lab:status` / `lab:stop` | Запустить, проверить или остановить три узла |
| `npm run lab:mine -- 1` | Создать блок и дождаться синхронизации |
| `npm run build` | Собрать интерфейс |
| `npm run start:dev` + `npm run dev` | API с разрешённым Origin Vite и интерфейс продавца на 5173; кошельки остаются на 4174/4175 |
| `npm test` | Проверки логики, политики подписи и HTTP-границ |
| `npm run test:integration` | Реальные HTTP-платёж и возврат; нужны три работающих приложения и devnet |
| `npm run test:lab` | Проверки узлов, отключения, восстановления и ветвления сети |
| `npm run test:signer` | Проверки PSBT и восстановления при потерянном ответе отправки |
| `npm run signer -- --help` | Сохранившийся CLI подписи покупателя |
| `npm run network:start` / `network:stop` | Старая отдельная regtest-сеть |
| `npm run legacy:api` / `test:legacy` | Старый regtest API на 4180 и его интеграционные проверки |

Ctrl+C в `npm start` останавливает три приложения. Узлы останавливаются отдельно через `npm run lab:stop`. Данные сохраняются. Интеграционные наборы запускайте последовательно: они меняют тестовую цепочку. Проверка `test:lab` также использует ранее запущенный regtest для проверки, что его цепь не затронута.

## Границы версии

Кабинет продавца получает ограниченные RPC-права чтения и создания адресов: подписывать и отправлять транзакции этим credential нельзя. Ключи покупателя доступны его отдельному локальному кошельку; возврат подписывает отдельный процесс кошелька продавца. Браузер не получает RPC-секреты и приватные ключи. Имя продавца в запросе ещё не удостоверено цифровой подписью.

Все процессы работают от одного пользователя ОС на одном компьютере. Такое разделение не защищает от скомпрометированного процесса с доступом к его файлам и не заменяет отдельное устройство покупателя. Нет авторизации продавцов, банков, обмена валют и независимых операторов. Сервисы предназначены только для loopback.

Кворумов мастернод нет. **InstantSend и ChainLocks не работают**: оплата подтверждается блоком. Runtime — официальный проверенный бинарный файл; C++ клиент форка не собран и консенсус не изменён.

## Структура

```text
merchant/       Devnet-счета, ограниченный RPC, сверка поступлений и возвратов
wallet/         Отдельные браузерные кошельки покупателя и продавца
signer/         PSBT, политика, журнал подписи и CLI
lab/            Три узла именованной devnet и мониторинг
server/         Старый regtest API и общие суммы/HTTP/RPC компоненты
network/        Установка runtime и прежняя regtest-сеть
web/            Интерфейс продавца, checkout и кошельков
tests/          Автоматические и реальные интеграционные проверки
.runtime/       Ключи, базы и бинарные файлы — исключены из Git
```
