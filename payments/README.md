# LAVEPAY 0.6

Локальная платёжная система: кабинет продавца, счета, QR, отдельный кошелёк
покупателя и возвраты с явным подтверждением продавца. По умолчанию используется
**собранный из исходников LAVE Core** и четырёхузловая devnet
**`lave-local-v1`** с тестовой валютой **LAVE**. Касса хранит только публичные
дескрипторы; ключи возвратов находятся на отдельном узле подписи.

Тестовые LAVE не имеют денежной стоимости. Публичная основная сеть,
международный приём реальных платежей и фиатные выплаты не запущены.
Доступность названия, доменов и товарных знаков не проверена.

## Запуск

Нужны Node.js 22.13+, npm и инструменты для сборки C++ клиента.
Зависимости и ограничения платформ перечислены в [LAVE-CORE.md](../docs/LAVE-CORE.md).
Сборка из исходников занимает существенно больше времени, чем сборка интерфейса.

```sh
cd payments
npm ci
npm run core:build
npm run lab:start
npm run core:verify
npm run build
npm start
```

`core:build` собирает локальные `laved` и `lave-cli`, записывает происхождение
сборки и контрольные суммы. `lab:start` использует этот клиент, создаёт отдельные
кошельки и добывает тестовые монеты. Это не загрузка готового официального
бинарного файла Dash и не доказательство воспроизводимости независимыми участниками.

На macOS `npm start` и `npm run start:merchant` запускают кассу в Seatbelt:
ей недоступны файлы кошельков, административные RPC-cookie и HTTP-сервисы
подписи на 4174/4175. Сервисы кошельков и владелец компьютера остаются
доверенными. На других ОС пока нужен явный запуск локального демо без этой
изоляции: `LAVEPAY_ISOLATION=off npm start`.

Откройте **http://127.0.0.1:4173**. Работают три приложения:

| Адрес                   | Назначение                                           |
| ----------------------- | ---------------------------------------------------- |
| `http://127.0.0.1:4173` | Кабинет продавца, checkout и мониторинг сети         |
| `http://127.0.0.1:4174` | Кошелёк покупателя: проверка и явная подпись платежа |
| `http://127.0.0.1:4175` | Кошелёк продавца: проверка и явная подпись возврата  |

## Мастерноды из кошелька

Откройте `http://127.0.0.1:4174/#masternodes`. Кошелёк проверяет наличие
1000 подтверждённых доступных LAVE и комиссии, отдельно запрашивает подпись
залога и регистрации, запускает локальный узел и показывает его состояние
и реальные выплаты. Остановка сохраняет блокировку; вывод залога требует
отдельной проверяемой транзакции. Один управляемый узел на роль кошелька.

`npm run payment-mn:start` поднимает шестнадцать базовых мастернод существующей
платёжной сети и формирует её кворумы. Подробности и правила блокировки —
[мастерноды кошелька](docs/WALLET-MASTERNODES.md).

## Касса без приватных ключей

Четыре узла LAVE: miner (RPC20001), merchant с watch-only кошельком `cashier`
(20002), customer (20003) и отдельный signer с приватным кошельком `merchant`
(20004). У кассы Core подтверждает `private_keys_enabled=false`; даже корректный
PSBT она не может подписать. Ограниченные RPC-права отдельно запрещают подпись,
отправку и экспорт ключей. Для тестового майнинга используется отдельный
ограниченный credential вместо административного cookie.

При обновлении существующей LAVE сначала остановите HTTP-приложения, затем
выполните `npm run lab:start`. Миграция сохраняет адреса, счета и ключи:
резервирует исходный приватный кошелёк, переносит его на signer, импортирует
публичные дескрипторы и метки адресов в кассу, проверяет баланс и сохраняет
оригинал в приватном архиве. Повторный запуск проверяет завершённую миграцию.
Кошельки Atlas не участвуют. Подробности и пути архива — в [LAB.md](docs/LAB.md).

## Прежний профиль Atlas

Старые кошельки, счета и тестовые DASH остаются в прежней цепочке
`atlas-local-v1`. Они не конвертируются в LAVE и не копируются в новую базу.
Для старого профиля явно задайте переменную для **каждой** команды:

```sh
LAVEPAY_NETWORK=atlas npm run lab:start
LAVEPAY_NETWORK=atlas npm start
# После остановки приложений:
LAVEPAY_NETWORK=atlas npm run lab:stop
```

Перед переключением профиля остановите приложения на 4173/4174/4175 и запустите
их с одинаковым значением переменной. Узлы двух профилей используют разные
RPC/P2P-порты и каталоги. LAVE хранит данные в `.runtime/lave/`; Atlas использует
прежние `.runtime/lab/`, `.runtime/merchant/` и `.runtime/signer/`. Интерфейс
получает валюту от сервера и неизменяемого запроса; неизвестную валюту он не
выдумывает. Сохранённые в браузере операции разделены по цепочке и её генезису.

## Платёж и возврат

1. Создайте счёт, например на `0.125` тестовых LAVE (или DASH в явно выбранном Atlas), и откройте страницу оплаты.
2. Перейдите в кошелёк покупателя и нажмите «Подготовить». Проверьте адрес, сумму, комиссию, итог, сдачу и сеть.
3. Отдельно подтвердите подпись и отправку. Открытие ссылки и подготовка сами по себе не отправляют монеты.
4. Вернитесь к счёту. После обнаружения перевода создайте тестовый блок; статус изменится на оплаченный.
5. Для возврата скопируйте адрес получения из кошелька покупателя, укажите его в счёте продавца и создайте запрос возврата.
6. В отдельном кошельке продавца подготовьте, проверьте и подтвердите возврат. После ещё одного тестового блока счёт покажет завершённый возврат.

QR содержит **ссылку на локальную страницу оплаты**, не запрос какой-либо основной сети. Все адреса localhost доступны только на этом компьютере; это пока не касса для клиентов в интернете.

Перезагрузка страницы восстанавливает сохранённую операцию. Повторное подтверждение уже отправленного запроса возвращает ту же транзакцию. Отмена доступна только для неподписанного подготовленного запроса. При неопределённом результате отправки сохраняются подписанные байты и txid — новый платёж автоматически не создаётся.

Частичная внешняя оплата учитывается, но блокирует новую автоматическую оплату полной суммы: требуется проверка продавцом. Переплата и позднее поступление отражаются в счёте. Возврат в этой версии — весь подтверждённый полученный объём; адрес явно задаёт продавец. Дополнительные поступления и конфликт возврата требуют проверки.

## Резервные копии кошельков

В кошельке покупателя или продавца можно скачать `.lavebackup`: зашифрованные
Core-кошелёк и журнал подписей. Задайте и повторите пароль. Используются
AES-256-GCM и scrypt; приложение не сохраняет пароль. Храните его отдельно:
без него копию открыть нельзя.

CLI экспортирует такую же копию и восстанавливает файлы только в новый каталог:

```sh
npm run backup -- --help
npm run backup -- export customer /absolute/private/path/customer.lavebackup
npm run backup -- restore customer /absolute/private/path/customer.lavebackup /absolute/private/path/recovered-customer
```

Пути — примеры; выберите существующий приватный родительский каталог. Пароль
вводится скрыто в терминале. Восстановление не заменяет и не загружает рабочий
кошелёк. В восстановленном журнале **новые подписи заблокированы**: разрешено
только повторить уже сохранённую подписанную транзакцию. Копия не знает о более
поздних платежах; автоматического снятия этой блокировки нет.

Шифруется экспортируемый файл, а не рабочие кошельки, исходный архив миграции
или файлы после восстановления. База счетов кассы и ключи LAVE-Q в эту копию
не входят. Workflow поддерживает LAVE, не Atlas. Подробнее — [WALLET.md](docs/WALLET.md).

| `npm run start:customer-wallet`                 | Только кошелёк покупателя, порт 4174                                                       |

| `npm test`                                      | Проверки логики, политики подписи и HTTP-границ                                            |
| `npm run test:integration`                      | Реальные HTTP-платёж и возврат; нужны три работающих приложения и devnet                   |
| `npm run test:lab`                              | Проверки узлов, отключения, восстановления и ветвления сети                                |
| `npm run test:signer`                           | Проверки PSBT и восстановления при потерянном ответе отправки                              |
| `npm run test:cashier`                          | Проверить watch-only кассу, повтор миграции и ограниченные RPC-права                       |

| `npm run mn:verify`                             | Проверки кворумов в отдельной цепочке LAVE-Q                                               |
| `npm run signer -- --help`                      | Сохранившийся CLI подписи покупателя                                                       |
| `npm run network:start` / `network:stop`        | Старая отдельная regtest-сеть                                                              |
| `npm run legacy:api` / `test:legacy`            | Старый regtest API на 4180 и его интеграционные проверки                                   |

Для `test:wallet-isolation` дополнительно нужен официальный Dash runtime как отдельная отрицательная тестовая фикстура: `npm run network:install`. Обычный запуск LAVE его не использует.

Для быстрых проверок платежей LAVE сначала дождитесь успешного `npm run payment-mn:start`
и `npm run payment-mn:verify`: свежей транзакции нужна подпись InstantSend перед
включением в блок. До готовности кворумов действует унаследованное ожидание до
600 реальных секунд. Кнопка создания блока проверяет готовность и фактическое
подтверждение платежа; при ожидании подписи предлагает повторить действие.

Ctrl+C в `npm start` останавливает три приложения. Узлы останавливаются отдельно через `npm run lab:stop`. Данные сохраняются. Интеграционные наборы запускайте последовательно: они меняют тестовую цепочку. Проверка `test:lab` учитывает доступные старые среды Atlas/regtest. Майнер может использоваться другой задачей, включая LAVEPAY MOVE: сохраняйте её кошельки и согласовывайте остановки или разрушительные сетевые проверки.

## Границы версии

Касса LAVE действительно watch-only, возврат подписывает отдельный Core-узел.
Ключи покупателя доступны его отдельному локальному сервису. Браузер не получает
RPC-секреты и приватные ключи. Имя продавца в запросе ещё не удостоверено
цифровой подписью, авторизации продавца и владельца кошелька пока нет.

На macOS изолирован именно процесс кассы. Узлы Core, сервисы подписи и владелец
компьютера остаются доверенными; это ещё не отдельное устройство покупателя и
не производственная модель хранения ключей. Все сервисы предназначены для
loopback. Банков, обмена валют и независимых операторов нет.

Платёжная LAVE поддерживает свои мастерноды и кворумы; монитор показывает
InstantSend/ChainLocks только по свежим данным этой цепочки. Статус счёта
`paid` по-прежнему требует подтверждения блоком. Отдельная
[лаборатория LAVE-Q](docs/MASTERNODES.md) сохраняется для экспериментов;
её результаты не применяются к счетам LAVE. Все узлы работают на одном компьютере.

Atlas сохраняет прежние три узла с официальным Dash Core и тестовыми DASH.
Исходники LAVE и локальные проверки не являются аудитом публичной сети или
завершённой экономикой валюты.

## Структура

```text
merchant/       Devnet-счета, ограниченный RPC, сверка поступлений и возвратов
wallet/         Отдельные браузерные кошельки покупателя и продавца
signer/         PSBT, политика, журнал подписи и CLI
lab/            Четыре узла LAVE, watch-only миграция и мониторинг (Atlas — три)
server/         Старый regtest API и общие суммы/HTTP/RPC компоненты
core/           Сборка и проверка локального LAVE Core
backup/         Зашифрованный экспорт Core + журнал, восстановление с блокировкой
isolation/      macOS Seatbelt для кассы и проверки границ
masternodes/    Отдельная девятиузловая лаборатория LAVE-Q
staking/        Залог, регистрация, узел и вывод из кошелька
payment-masternodes/  Шестнадцать базовых мастернод платёжной сети LAVE
network/        Официальный Dash runtime для Atlas и прежней regtest-сети
web/            Интерфейс продавца, checkout и кошельков
tests/          Автоматические и реальные интеграционные проверки
.runtime/       Ключи, базы и бинарные файлы — исключены из Git
```
