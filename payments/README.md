# Atlas Pay

Рабочий прототип платёжной системы на базе Dash Core: кабинет продавца, счета, QR-оплата, подтверждение и возврат через настоящие транзакции **локальной regtest-сети**.

Название Atlas Pay временное. В прототипе используются тестовые DASH без денежной стоимости. Собственная публичная монета и международный приём реальных платежей ещё не запущены.

## Быстрый запуск

Нужны Node.js 22.13+ и npm. Автоматическая установка узла поддерживает macOS и Linux на ARM64/x64. На этом компьютере проверяется macOS ARM64. Docker не нужен.

```sh
cd payments
npm ci
npm run demo
```

Откройте **http://127.0.0.1:4173**. Первый запуск загружает закреплённую версию Dash Core 23.1.8, проверяет SHA-256, создаёт отдельные тестовые кошельки и добывает тестовые монеты. На macOS ARM64 неподписанные официальные CLI-файлы при необходимости получают локальную ad-hoc подпись после проверки архива; системные настройки безопасности не изменяются.

## Первый платёж

1. Создайте счёт, например на `0.125` тестовых DASH.
2. Откройте страницу оплаты или скопируйте ссылку `/pay/<id>`.
3. Нажмите оплату из тестового кошелька. Сервер отправит реальную транзакцию из отдельного кошелька `payer`.
4. Создайте тестовый блок соответствующей кнопкой. После подтверждения счёт станет оплаченным.
5. Выполните возврат и создайте ещё один блок. Возврат — новая транзакция из кошелька `merchant` в тестовый кошелёк покупателя.

QR содержит Dash payment URI с адресом **regtest**. Он предназначен для совместимого тестового окружения, не для обычного кошелька основной сети. Ссылка на localhost работает на этом компьютере; её нельзя отправить покупателю в интернете как публичную кассу.

## Команды

| Команда | Назначение |
|---|---|
| `npm run network:start` | Установить и запустить отдельную regtest-сеть, подготовить кошельки |
| `npm run network:status` | Проверить узел и баланс тестового кошелька |
| `npm run build` | Собрать веб-интерфейс |
| `npm start` | Запустить локальный API и интерфейс на порту 4173 |
| `npm run start:dev` | Запустить API с разрешённым локальным адресом Vite для разработки |
| `npm run dev` | Запустить Vite на 127.0.0.1:5173; API запускается отдельно через `npm run start:dev` |
| `npm test` | Запустить автоматические тесты платёжного сервера |
| `npm run test:integration` | Проверить оплату и возврат реальными тестовыми транзакциями; нужны работающие узел и API |
| `npm run network:stop` | Остановить локальный узел |

Сервер останавливается через Ctrl+C в терминале, где запущен `npm start`. Узел останавливается отдельно. Данные сохраняются между запусками.

## Что обеспечивает прототип

- Точные суммы в целых сатоши; входной формат — десятичная строка до восьми знаков.
- Сохранение счетов и журнал операций в SQLite.
- Ключи идемпотентности для защиты от повторного создания, оплаты и возврата.
- Различение частичной оплаты, обнаруженной транзакции и подтверждённого платежа.
- Отдельный учёт переплаты, срока счёта и возврата.
- Реальные адреса, QR-коды и идентификаторы транзакций; данные загружаются из узла.
- Доступ к RPC только через loopback и cookie; приватные ключи не передаются браузеру.
- Проверка `regtest` перед денежными операциями.

## Границы текущей версии

Это один изолированный узел без кворумов мастернод. InstantSend и ChainLocks здесь **не работают**; статус оплаты означает подтверждение блоком. Официальный бинарный файл используется как эталонный runtime, новый C++ клиент не собран и консенсус не изменён.

Локальные кнопки оплаты и возврата используют тестовые кошельки сервера. Это инструмент разработки, а не готовая модель хранения средств клиентов. Нет публичного доступа, авторизации продавцов, фиатных выплат, обмена валют, эквайринга или подключённых банков. Сервисы нельзя открывать в интернет.

## Структура

```text
network/        Установка и управление локальным Dash
server/         API, SQLite, суммы, сверка с блокчейном
web/            React-интерфейс продавца и оплаты
tests/          Автоматические и реальные интеграционные проверки
docs/           Сеть, безопасность, дальнейшие этапы
.runtime/       Локальные ключи, база и бинарные файлы — исключены из Git
```
